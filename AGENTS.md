# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Durable prototype decisions

- Permission assignment follows the supplied collaborator-list reference: show each member in a row with a right-aligned permission dropdown, rather than a checkbox matrix. Support quick presets plus a custom panel for the four independent capabilities, searchable multi-member addition with individual permission choices, removal/undo and explicit final save/cancel. Preserve the light product styling, creator protection, inherited permissions and public-reading constraints; do not introduce link-sharing or a separate download capability from the reference.

- The root/default entry is an independent 产品说明 page outside the prototype shell, at `#/overview`. It explains the product's business framework, detailed feature tables, space boundaries, independent permissions, typical workflows and current prototype limits for business readers. Entering the prototype is explicit; existing homepage and document deep links keep working, while the retired share-link route is unavailable. A restrained help entry returns from the prototype to the explanation.
- New content and uploads initiated inside a knowledge library are fixed to that current library; render its name as read-only and allow choosing only its directories. Only the homepage's general creation entry chooses among libraries. The empty-folder creation entry must expose the same 文档 / 表格 / 幻灯片 / 文件夹 menu as the top 新建 control.
- Ordinary move/copy operations are restricted to directories in the source knowledge library, including when invoked from the homepage. Mixed-library batch selections cannot move/copy. Copies have an editable duplicate name, and batch copies generate unique duplicate names. Personal→shared conversion and Plaza publication remain dedicated flows, separate from ordinary move/copy.
- Sharing means selecting registered internal members, with persisted recipient records and a recipient-side homepage entry. Remove share-link generation/copy/expiry/revocation interfaces and retire the old share-link route. Share capability alone cannot authorize new viewers: only creators/managers can explicitly grant missing view access, and sharing an inherited file to a new viewer requires confirming independent permissions while retaining existing rights. Private personal libraries must first convert to shared libraries.
- Show one signed-in account (the existing primary user 周宁), with a normal static user avatar/name in the sidebar. Remove the identity-preview switcher and browser-storage/demo labels from the product shell. Other people remain available as collaborators and permission recipients; they are not switchable login identities.
- Remove the 管理后台 module and its navigation entry for now. Its former URL must not render an administration screen.
- 问AI shares the knowledge-management modules' compact typography, spacing, borders, buttons, empty/error states and dialogs. Keep its question, scope/attachment selection, optional skills/experts, history management and editable/saveable output flows functional within that common visual system.
- Keep 问AI simple: ask a question → optionally select knowledge/attachments → read the answer and sources → ask a follow-up or save the result. Remove 计划模式 and its confirmation steps. Remove the unconfigured web-search entry. Skills and experts remain optional, compact secondary controls; do not add complex workflow orchestration.
- All AI-oriented capabilities belong in the dedicated “问AI” workspace. Treat it as the complete AI workbench for prompting, knowledge context, skills/experts, attachments, voice input, task execution, results, citations, and conversation history; do not scatter new AI entry points across unrelated knowledge-management pages.
- Knowledge Plaza is readable by every user. Any user may create content for it, but new content starts as private/draft (“待发布”); only an explicit publisher confirmation makes it visible to everyone in the Plaza.
- Shared knowledge-base access is a set of independent capabilities, not mutually exclusive roles: 查看, 编辑, 分享, 管理. The creator always has all capabilities. Only people with 管理 may invite, remove, or change member permissions; 编辑 alone never expands access scope.
- Knowledge can be promoted through an explicit publish/transfer path: 个人知识库 → 共享知识库 → 知识广场. Preserve provenance and require the appropriate confirmation/permissions at each step.
- The Shared Knowledge Base view includes the functional filters “全部 / 我创建的 / 与我共享” so users can distinguish content they administer from content they may only consume or contribute to.
- Personal Knowledge Base contains only the current user's own libraries. Do not show redundant “全部 / 我创建的” ownership tabs there; retain search, sort, and view controls.
- Keep controls and copy specific to the current business context. Personal-library cards omit repetitive creator identity, and personal documents describe owner-only access rather than implying externally shareable grants. Library type is fixed when creating from a category page; it is selectable only from the homepage and read-only in settings.
- Homepage “与我共享” contains accessible content from shared libraries owned by others, not Plaza content. “最近访问” uses the current user's visit timestamps and defaults to visit-time sorting. Empty folders, no favorites, no recent visits and no search results require different guidance; do not offer a no-op “clear filters” action when no filter exists.
- The left-nav “主页” is the knowledge workbench: retain the recent-document entry point and add quick creation, actionable pending items (including Plaza drafts), quick access to knowledge bases, and compact knowledge updates. Keep AI-specific work in 问AI instead.
- Homepage acceptance must reach end results: create/edit/save/reload, upload/persist/preview/download, rename/move/delete/restore, and publish/read as another identity. An opened dialog alone is not a completed interaction check. Persist original uploads in IndexedDB; do not simulate uploads with filename-only records.
- The five knowledge-management modules (主页 / 知识广场 / 共享知识库 / 个人知识库 / 回收站) share one capability and content model. Viewing, editing, internal sharing and managing are independently selectable. Personal libraries remain owner-only; internal recipients can gain view rights only through explicit creator/manager confirmation. Library creators retain all rights and library managers retain document permission administration.
- Promotion changes a personal library to a restricted shared library with fresh grants. Publishing creates a traced Plaza draft copy and preserves the source. Every new item or edit in an already-public library also requires confirmation before becoming public.
- Ordinary move/copy remains within the source library and resets independent grants to inherit the target directory. Restoring to the original location retains grants; restoring elsewhere inherits destination grants. Recursive deletion/restoration must preserve items deleted earlier in separate batches, and restore-name collisions can be resolved by changing the restore name.
- Knowledge management includes persistent uploads, document edit/save/version restore/comments, explicit permission editing, internal-member sharing, access requests and decisions, nested folders and batch file actions. 问AI uses the same product shell; 管理后台 is currently excluded.
- Removing a shared-library member (or clearing all their library capabilities) also removes their independent grants within that library. Changing just one capability preserves deliberate file-level overrides. Explain this in the permission editor.
- The creation menu contains only 文档 / 表格 / 幻灯片 / 文件夹. Newly created documents, spreadsheets and slide decks open immediately in a separate browser tab in edit mode; saving updates the originating list through browser storage synchronization. Folders stay in the current knowledge-library context.
- Recursive copying requires view access to every active descendant; recursive moving/deleting requires management of every affected descendant. Ordinary cross-library move/copy is forbidden. Relocated restores clear source grants, inherit the destination and preserve original authorship and provenance.
- Approving access to a file that currently inherits permissions must explicitly show and confirm the switch to independent permissions. Cancelling leaves both the request and inheritance unchanged.
- All remaining modules, including 问AI, use the same sidebar, current-user pins, static account information and collapse state. Do not add identity switching, administration or demo-data reset controls to ordinary navigation.
- Invalid routes show a recovery page; route changes close context-specific dialogs. Disabled creation controls explain the missing permission or save location. Library names are limited to 40 characters with a visible counter, and long existing names must wrap or truncate without breaking layout.
- 问AI conversations persist per identity in browser storage. History opens the complete conversation, including after source navigation or reload; empty/whitespace-only prompts cannot create a conversation.

- Render the application as a direct full-browser page without an outer black canvas, inset frame, page label, or rounded page shell.
- Use restrained Codex-like UI typography and density for the sidebar and lightweight action controls.

- Typing `/` opens a separate full-width command palette above the composer, with skill/expert tabs and dense single-line rows (icon, name, truncated description, pin affordance). Choosing an item removes the temporary slash and applies the existing skill-chip or expert-selection behavior.
- The composer `@` entry is labeled “知识”, and its placeholder hint says `“@”指定知识`; slash hints say “调用技能或专家”.
